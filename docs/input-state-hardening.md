# 입력과 로컬 상태 보호

2026-09-22 기준. ATR 기간·배수·Stop 상향 규칙·알림 임계값·시장 시간 정책은 기존과 같다.

## 계산 입력

ATR 계산에 사용하는 H/L/C 전체 이력은 숫자이며 유한한 양수여야 한다. High/Low/Close 관계와 인덱스의 순서·중복·결측을 검사한다. Wilder 초기화 이후의 마지막 ATR이 최신 입력 행과 일치해야 Stop을 계산한다. 결측을 제거해 과거 ATR을 최신값처럼 사용하는 경로는 허용하지 않는다.

Open은 ATR 산식의 필수 입력이 아니다. 수집기가 최신 부분 봉의 시가를 확보하지 못했어도 정상 H/L/C로 계산한다. 갭 알림의 Open 처리 방식은 그대로 유지한다.

계산할 수 없는 종목은 Stop 저장과 ATR 요약에서 제외하고 실패 건수로 기록한다. 다른 정상 종목은 계속 처리하되 문제가 있었던 GitHub Actions 실행은 종료코드 1을 반환한다. 데이터 날짜나 휴장일 정책, 별도 빠른 트리거의 전략 판단은 이번 변경에 포함하지 않는다.

## 포트폴리오 출처

- `GDRIVE_PORTFOLIO_FILE_ID`를 명시하면 Drive가 선택된다. 자격증명 누락·로드 실패·잘못된 목록이면 중단하며 `STOCK_LIST`로 전환하지 않는다.
- Drive를 선택하지 않았다면 `STOCK_LIST`의 JSON 객체, 그룹별 문자열 목록, 비어 있지 않은 전체 목록을 검사한다. 잘못된 값은 원문을 로그에 남기지 않는다.
- 서비스계정은 상태 동기화에도 쓰므로, 정상 `STOCK_LIST`와 서비스계정만 있는 구성은 계속 허용한다.
- 아무 출처도 설정하지 않은 로컬 개발에서만 기존 예시 목록을 사용한다. GitHub Actions나 자격증명만 있는 불완전한 구성에서는 예시 목록으로 실행하지 않는다.
- 잘못된 명시 설정은 상태 pull·가격 수집·로컬 스케줄러 시작 전에 중단한다. 로컬 포지션 관리 CLI는 별도로 사용할 수 있다.

## 상태 파일

`positions`, `alert_log`, `done_windows`의 구조·값 타입을 검사한다. 비유한 숫자, 중복 JSON 키, 잘못된 날짜, 불완전한 포지션은 거절한다. 구버전 선택 필드의 생략과 알 수 없는 확장 필드는 허용하고 기존 포지션의 확장 필드는 갱신 후에도 보존한다.

존재하는 파일이 손상됐다면 빈 상태로 대신하거나 유효한 일부 레코드만 저장하지 않는다. 고정된 오류 메시지에는 상태 값·키·파일 경로를 포함하지 않는다. 로컬 파일이 처음부터 없는 경우에는 기존 로컬 초기화 동작을 유지한다.

저장할 내용을 검증한 뒤 같은 디렉터리의 임시 파일에 쓰고 flush/fsync한다. 임시 파일을 다시 읽어 검증하고 내용이 일치할 때 `os.replace`로 교체한다. 교체 전 저장 실패는 기존 파일을 보존한다. 후속 구현에서는 경로별 RLock과 OS 프로세스 잠금으로 전체 상태 트랜잭션을 직렬화한다.

Drive 업로드 전에도 같은 스키마를 검사한다. 후속 MD5 사전 충돌 검사와 로컬 프로세스 잠금의 현재 범위는 [상태 충돌 보호](state-conflicts.md)를 따른다. 원자적 원격 CAS와 알림 발송·저장을 하나의 거래로 묶는 보장은 제공하지 않는다.

## 검증

관련 회귀는 `tests/test_atr_input_validity.py`, `tests/test_portfolio_configuration.py`, `tests/test_state_integrity.py`, `tests/test_input_state_integration.py`에 있다. 모두 합성 가격·가상 설정·임시 상태와 mock Drive/Telegram을 사용한다.

개발 검증에서는 코드만 복사한 격리 환경에서 자격증명 환경을 제거하고 dotenv·외부 통신·운영 경로 접근을 차단한 뒤 전체 `tests`를 실행했다. 실제 Drive 상태, 포트폴리오, 수집 API, Telegram 전송 및 workflow dispatch는 검증 대상이 아니다.
