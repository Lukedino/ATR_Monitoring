# 실행 실패 처리와 합성 검사

2026-09-22. 입력·로컬 상태 보호 다음으로 ATR-R10의 오류 전달과 R11의 공개 로그·CI 하위 범위를 보완했다. 시장 날짜, ATR 배수, Stop 상향·알림 판단, PA 실행 창과 거래 정책은 변경하지 않았다.

## Drive와 작업 실패

Drive 의존성 초기화, 인증, 서비스 생성, 다운로드, 업로드 준비·전송 오류를 단계별 고정 문구의 `StateSyncError`로 전달한다. 예외 원문·URL·응답 본문·파일 ID·자격증명과 원래 traceback 체인은 출력하지 않는다. 실패한 pull은 로컬 정상본을 교체하지 않고, 불확실한 push는 성공 체크섬을 갱신하지 않으며 자동 재전송하지 않는다. 원격 CAS나 다중 writer 충돌 보호를 제공하는 변경은 아니다.

작업 중 예상하지 못한 예외도 종류만 기록하고, 이미 성공한 작업의 상태 push를 시도한 뒤 종료코드 1로 끝난다. push 실패 또한 실패 목록에 포함한다. 기존 알림 성공 후 Stop 저장 순서는 유지한다.

## 공개 로그

GHA에서는 설정·외부 라이브러리 import 전에 예외 보호를 설치한다. 전체 로깅 초기화 뒤에는 기존 LogRecordFactory를 보존하며 메시지·예외·stack 정보를 정제한다. 새 핸들러와 propagate=False 로거도 이 경계를 통과한다. 예외 처리 훅 자체의 로깅 실패는 고정 문장만 출력한다.

검증된 상태 pull 결과의 positions/alert_log 키를 기존 포트폴리오 마스크에 추가한다. 상태 파일을 로그 모듈이 별도로 읽지 않으며 가격·계좌·기타 확장 필드를 마스크 명령에 넣지 않는다. HMAC 가명, 짧은 심볼의 토큰 경계, 기존 GHA add-mask를 유지한다. 일반 로컬 실행은 종목을 표시하는 기존 정책을 유지한다. 임의 서드파티의 직접 stdout 출력 전체를 가로채는 기능은 아니다.

## 운영 워크플로

운영 작업은 기존 PA의 workflow_dispatch와 단일 writer 직렬화를 유지한다. 허용된 6개 작업명만 환경변수로 받아 검증한 뒤 실행한다. 표현식 값을 셸 코드에 직접 삽입하지 않는다.

전체 작업 상한은 30분, 모니터 단계는 20분, 폰트 단계는 2분이다. 이 상한은 무한 대기를 제한하기 위한 값이며 실제 운영 소요시간의 측정 결과는 아니다. 폰트 설치 실패는 차트용 부수 단계 실패로 남기고 핵심 감시는 계속한다.

일반 단계 실패 후에는 표준 라이브러리만 사용하는 보완 알림을 시도한다. 기존 Telegram 대상에 고정 문장과 숫자 실행 번호만 보내며 URL/응답/예외 원문을 로그로 출력하지 않는다. 요청은 1회·10초 제한이고, 리디렉션을 거부하며 HTTP 200과 JSON ok=true를 모두 확인한다. 앱의 실패 알림과 중복될 수 있다. checkout 실패로 스크립트가 없거나 Python을 사용할 수 없는 경우, 전체 작업 취소·시간 초과·실행 자체가 없었던 경우의 발송은 보장하지 않는다. 독립 데드맨이나 PA 운영 감시를 대신하지 않는다.

시간 제한·부수 단계 실패 처리의 의미는 [GitHub 공식 workflow 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)를 따른다.

## 안전한 검사 경로

`requirements-dev.txt`는 운영 의존성과 [pytest 9.1.1](https://pypi.org/project/pytest/9.1.1/)을 고정한다. `python scripts/run_offline_tests.py`는 코드·테스트·워크플로만 임시 디렉터리에 복사하고 환경을 정리한 뒤 pytest를 실행한다. `.env`, 실제 상태·포트폴리오·분석 파일은 복사하지 않는다.

기존 체크아웃과 허용된 라이브러리/OS 시간대·폰트 데이터 밖 읽기, 임시 사본 밖 쓰기, dotenv, 네트워크, 자식 프로세스 실행을 차단한다. Windows 임시 디렉터리 ACL과 Linux 시간대·폰트 경로 차이를 처리한다. 라이브러리의 IPv6·fontconfig 탐색은 실제 연결이나 자식 프로세스를 만들지 않는 대역으로 제한한다. 코드 사본은 실패 분석을 위해 OS 임시 디렉터리에 남는다.

`--self-check`는 가짜 이름·합성 파일만 대상으로 DNS, 프로세스, 사본 밖 읽기/쓰기, dotenv 차단을 확인한다. 실제 차단 이벤트가 전체 검사 중 발생하면 테스트가 모두 성공해도 실행은 실패한다. 이 실행기는 의도치 않은 테스트 I/O를 막기 위한 장치이며 악성 Python이나 native extension의 보안 sandbox는 아니다.

별도 CI는 자격증명 없이 Linux Python 3.11/3.12에서 차단 자체 검사와 전체 회귀를 실행한다. 실제 포트폴리오·상태·Drive·Telegram·시세 수집이나 운영 workflow dispatch는 검증 수단으로 사용하지 않는다. CI 실행 결과는 해당 커밋의 Actions 결과로 확인해야 하며 로컬 Python 통과만으로 원격 검증 완료라 하지 않는다.
